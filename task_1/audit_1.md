## 3. Сильные стороны работы

1. **Полностью числовой бенчмаркинг с явной шкалой и выводами.** Раздел 4 (`solutuion_1_fix.docx`, **стр. 4–5**) задаёт явную шкалу 0–5 с описанием каждого уровня, все 60 ячеек таблицы (10 функций × 6 колонок включая «Мой проект») заполнены числами, после таблицы — два содержательных абзаца с привязкой к строкам матрицы.
2. **Согласованная колонка «Мой проект».** Числовые оценки во всех строках согласованы с описанием функционала во вступлении (`solutuion_1_fix.docx`, **стр. 4–5**): «отчётность» и «статистика» = 4, «учебный процесс» и «интеграции» = 2 с прямым объяснением «не LMS, MVP без интеграционного контура».
3. **Полностью прозрачный SLA-блок с источниками измерения и обоснованием порогов.** Раздел 5 (`solutuion_1_fix.docx`, **стр. 5–6**) задаёт контекст эксплуатации (режим, пользователи, объём, критичные процессы, операционные определения «стандартного файла» и «актуальной записи»). В разделе 6 (стр. 6–10) для каждого из 18 SLA указаны источник проверки и обоснование выбора порога.
4. **Корректные SWOT-таблицы со сводным выводом для проекта.** В разделе 3 (`solutuion_1_fix.docx`, **стр. 2–3**) — пять SWOT с методологической корректностью (S/W — внутреннее, O/T — внешнее) + сводный «Вывод по SWOT» с позиционированием проекта (узкая специализация против тяжёлых ERP).
5. **Снятие двусмысленности по GetCourse.** В разделе 2 (`solutuion_1_fix.docx`, **стр. 2**) убрано слово «прямые», для GetCourse явно зафиксирован статус «частичный аналог» — апелляция «GetCourse — не из той ниши» теряет силу.

## 4. Замечания по блокам

- `solutuion_1_fix.docx`**, стр. 1–2 (раздел 2) — карта сегментов рынка не введена:** перечень всё тех же 5 систем, без явной разметки сегментов (4–5 категорий) и представителей недостающих классов решений: **российские академические ИС / LMS вузовского контура** (примеры ориентира: Tandem.University, Modeus, Naumen University, BARS Education), **корпоративные LMS для ДПО** (iSpring Learn, Teachbase), **open-source LMS** (Moodle), **status quo без специализированной ИС** (Excel, почта, разрозненные регистры). Критерий «Полнота покрытия сегментов» — **6 из 8**. **Как исправить:** перед списком конкурентов ввести подраздел «Сегменты конкурентного рынка» с 4–5 категориями и хотя бы по одному представителю в каждой; для исключённых сегментов дать одну строку обоснования.
- `solutuion_1_fix.docx`**, стр. 2 (раздел 2) — позиционирование GetCourse в карте сегментов:** GetCourse теперь явно «частичный аналог», но он по-прежнему остаётся в общем списке без отнесения к отдельной категории. Если ввести карту сегментов (см. предыдущий пункт), GetCourse логично перенести в категорию «Платформы онлайн-обучения» с отметкой «непрямой конкурент / для широты рынка». Альтернатива — заменить GetCourse на профильный продукт для back-office ДПО во вузе. Критерий «Релевантность теме ВКР» — **9 из 12**. **Как исправить:** при введении карты сегментов отнести GetCourse к отдельной категории с явным статусом «непрямой конкурент»; либо заменить на профильную ИС.
- `solutuion_1_fix.docx`**, стр. 2–3 (раздел 3) — нет стратегического вывода по каждому конкуренту:** добавлен общий «Вывод по SWOT», но в исходном замечании ожидался разбор «3–5 предложений „что значит для проекта“» по **каждому** конкуренту (где их сильные стороны — наша угроза, где слабые — наш шанс). Сводный вывод закрывает критерий частично. Критерий «Практическая применимость SWOT» — **6 из 8**. **Как исправить:** под каждой SWOT-таблицей в разделе 3 добавить 2–3 строки «Что значит для проекта»: какую слабость конкурента можно использовать как преимущество (например, «сложность 1С: Университет → наш продукт продаёт простоту»), какая сильная сторона — это барьер.
- `solutuion_1_fix.docx`**, стр. 2–3 (раздел 3) — обобщённые Opportunities у части конкурентов:** у трёх из пяти конкурентов (1С: Университет, GetCourse, Парус) Opportunities — общие фразы «расширение функциональности / интеграции». У Галактики и 1С: Учебный центр — конкретнее («Интеграция с государственными ИС», «Рост популярности ДПО»). Критерий «Полнота S/W/O/T» — **6 из 8**. **Как исправить:** для трёх конкурентов с обобщёнными Opportunities заменить их на конкретные внешние возможности рынка (например, «изменения в нормативной базе ДПО», «спрос на цифровизацию приёмной кампании», «рост рынка корпоративного обучения»).
- `solutuion_1_fix.docx`**, стр. 4–5 (раздел 4) — отсутствие количественных рыночных метрик в бенчмаркинге:** введена шкала 0–5 (это закрывает основной пробел), но в исходном `scoring_1.md` дескриптор 4/4 предполагает не только числовые шкалы, но и **количественные метрики сравнения** (% покрытия рынка, число клиентов, число образовательных учреждений-внедрителей). Критерий «Числовые шкалы / метрики сравнения» — **9 из 12**. **Как исправить:** добавить колонку «Доля внедрений в вузах ДПО» или «Число известных внедрений» с укрупнёнными числами (хотя бы порядка величины: 100+ вузов, 10+ корпоративных клиентов, неизвестно).
- `solutuion_1_fix.docx`**, стр. 5 (раздел 4) — выводы по бенчмаркингу не оформлены как мини-таблица:** добавленный текст со ссылками на строки матрицы — это уже уровень дескриптора 3/4. До 4/4 не хватает компактной таблицы вида «**Преимущества проекта** vs **Пробелы проекта**» с конкретными строками матрицы в каждой колонке. Критерий «Обоснованность выводов из бенчмаркинга» — **3 из 4**. **Как исправить:** после абзацев «Вывод по бенчмаркингу» добавить мини-таблицу 2 столбца × 4–5 строк: слева — функции с оценкой 4–5 у проекта (импорт Excel, документы, потоки), справа — функции с оценкой 0–2 (учебный процесс, интеграции).

**Прогноз перехода категорий.** Текущая база — **138 / 156** (~88,5%, «Отлично»). Эффекты в правой колонке — диапазоны по дескрипторам `scoring_1.md`, не гарантии. Эффекты P1 пересекаются: например, карта сегментов одновременно влияет на «Полноту сегментов» и «Релевантность ВКР» (через перепозиционирование GetCourse). Простое суммирование верхних границ диапазонов завысит прогноз.

Условные сценарии (не гарантии; зависят от полноты внедрения каждой рекомендации):

- **Стабилизация в середине «Отлично» (~91–92%):** реализовать любые две P1 на минимальном уровне дескрипторов → расчётный прирост **+5…+8 баллов**, диапазон **143–146 / 156** (~92–94%).
- **Верх «Отлично» (~95%):** все три P1 + одна P2 → расчётный прирост **+9…+12 баллов**, диапазон **147–150 / 156** (~94–96%).
- **Близко к 156/156:** все P1 + все P2 — реалистичный, но не гарантированный сценарий; требует развёртывания каждого пункта на дескриптор 4.
